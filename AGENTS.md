# Development workflow

This repository uses GitHub Spec Kit for spec-driven development.

For new features and behaviour changes, follow:

1. `$speckit-specify`
2. `$speckit-clarify` when requirements are ambiguous
3. `$speckit-plan`
4. `$speckit-checklist`
5. `$speckit-tasks`
6. `$speckit-analyze`
7. `$speckit-implement`
8. `$speckit-converge`

For defects, follow `$speckit-bug-assess`, `$speckit-bug-fix`, and `$speckit-bug-test`.

Read `.specify/memory/constitution.md` before creating or changing a specification, plan, task list, or source file. Keep changes local-first, least-privilege, test-backed, and focused on the translation experience.

Do not commit or push unless the user explicitly asks.
